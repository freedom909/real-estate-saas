## 1. 目的・位置づけ

### 1.1 目的

本システムは、宿泊施設の運営者と宿泊者を対象として、宿泊施設情報、予約、ユーザーおよび運営管理に関する業務を一元的に管理することを目的とする。

本システムにより、宿泊施設の登録・公開から予約、予約管理、運営管理までの業務を効率化し、利用者の利便性および運営者の管理性を向上させる。

### 1.2 システム化の目的

本システムでは、以下の業務をシステム化の対象とする。

* ユーザー認証・ユーザー管理
* 宿泊施設管理
* 宿泊施設検索・閲覧
* 予約管理
* Tenant / 組織単位での運営管理
* 管理者によるシステム管理
* 監査・操作履歴管理

### 1.3 基本的な考え方

本システムは、単一ユーザーによる単純な予約管理ではなく、宿泊施設の運営主体と利用者を区別し、運営単位ごとに適切な業務管理を可能とする。

# 2. 対象範囲

## 2.1 対象業務

本システムの対象業務は以下とする。

1. ユーザー登録・認証
2. ユーザー情報管理
3. Tenant / 組織管理
4. Membership 管理
5. 宿泊施設管理
6. 宿泊施設検索・閲覧
7. 予約管理
8. 管理者業務
9. 監査・操作履歴管理

## 2.2 対象ユーザー

本システムでは、以下の利用者を想定する。

* 未認証ユーザー
* CUSTOMER
* HOST
* STAFF
* MODERATOR
* AGENT
* OWNER
* ADMIN
* SUPER_ADMIN

なお、権限については「8. 権限要件」に定義する。

## 2.3 対象外

現時点では以下を本システムの必須対象外とする。

* AIによる完全自動的な業務判断
* 人間による承認を必要とする業務の完全自動化
* 絶対的な無人運営
* 未定義の外部サービスとの自動連携
* 要件として明示されていない業務領域

# 3. 業務要件

## 3.1 ユーザー業務

利用者は、自身の認証状態に応じて本システムを利用できること。

利用者は、自身に許可された範囲でユーザー情報を管理できること。

## 3.2 宿泊施設業務

宿泊施設の運営者は、担当する宿泊施設を登録・管理できること。

宿泊施設について、利用者が閲覧可能な情報を提供できること。

宿泊施設の公開状態を管理できること。

## 3.3 予約業務

宿泊者は、公開されている宿泊施設を選択し、予約を作成できること。

予約について、予約状況を確認できること。

予約者は、自身の予約を管理できること。

運営者および管理権限を持つ利用者は、許可された範囲で予約を管理できること。

## 3.4 Tenant / 組織業務

宿泊施設の運営を組織単位で管理できること。

ユーザーは、所属する組織に応じて利用可能な業務を区別できること。

組織に所属するユーザーについて、所属状態および役割を管理できること。

# 4. システム化要件

## 4.1 認証

本システムは、ユーザーを識別するための認証機能を提供すること。

OAuth等の外部認証方式を利用できること。

認証済みユーザーについて、認証状態を管理できること。

ログアウト後は、認証された状態で保護された機能を利用できないこと。

## 4.2 ユーザー管理

ユーザーを一意に識別できること。

ユーザーの基本情報を管理できること。

ユーザーのシステム上の役割を管理できること。

## 4.3 Tenant / Membership

ユーザーと組織との所属関係を管理できること。

ユーザーが複数の組織に所属する場合、それぞれの所属状態を区別できること。

組織ごとにユーザーの役割を管理できること。

## 4.4 宿泊施設管理

宿泊施設について、以下の情報を管理できること。

* 基本情報
* 所在地
* 料金
* カテゴリ
* 設備・アメニティ
* 写真
* 公開状態
* 運営・所有に関する情報

## 4.5 予約管理

予約について、以下の情報を管理できること。

* 予約者
* 宿泊施設
* 宿泊期間
* 予約状態
* 料金
* 作成日時
* 更新日時

予約状態の変更について、利用者の権限に応じて制御できること。

## 4.6 管理機能

管理権限を持つ利用者は、システム全体または許可された管理範囲について管理業務を実施できること。

## 4.7 監査・操作履歴

重要な管理操作について、操作履歴を確認できること。

# 6. 非機能要件

## 6.1 可用性

システムは、通常の業務時間帯において安定して利用できること。

## 6.2 性能

通常のユーザー操作に対して、業務上支障のない応答時間を確保すること。

## 6.3 拡張性

今後の利用者増加、宿泊施設増加および業務機能追加に対応できること。

## 6.4 保守性

機能追加および仕様変更を行えるよう、保守可能なシステムであること。

## 6.5 追跡可能性

重要な業務操作について、誰が、いつ、何を行ったかを確認できること。

# 7. 業務フロー

主要業務は以下の流れとする。

### 7.1 宿泊施設登録

```text
宿泊施設運営者
    ↓
宿泊施設情報入力
    ↓
宿泊施設登録
    ↓
内容確認
    ↓
公開
    ↓
利用者が閲覧可能
```

### 7.2 予約

```text
利用者
    ↓
宿泊施設検索
    ↓
宿泊施設詳細確認
    ↓
予約情報入力
    ↓
予約作成
    ↓
予約状態管理
```

### 7.3 予約管理

```text
予約
 ↓
確認
 ↓
予約状態更新
 ↓
必要に応じてキャンセル
 ↓
チェックイン
```

# 10. 権限要件

本システムでは、利用者のシステム上の役割および組織への所属状況に応じて、利用可能な業務を制御すること。

## 10.1 基本権限

| Role        | Listing  | Booking  | User / Member | Admin |
| ----------- | -------- | -------- | ------------- | ----- |
| GUEST       | 閲覧       | -        | -             | -     |
| CUSTOMER    | 閲覧       | 自分の予約    | 自分のみ          | -     |
| STAFF       | 組織内の許可範囲 | 組織内の許可範囲 | 許可範囲          | -     |
| MODERATOR   | 組織内の許可範囲 | 組織内の許可範囲 | 許可範囲          | -     |
| HOST        | 管理可能     | 自分の範囲    | -             | -     |
| AGENT       | 許可範囲     | 許可範囲     | 許可範囲          | -     |
| OWNER       | 組織内管理    | 組織内管理    | 組織内管理         | -     |
| ADMIN       | システム管理範囲 | システム管理範囲 | 管理可能          | ○     |
| SUPER_ADMIN | 全体管理     | 全体管理     | 全体管理          | ○     |

### 10.2 権限に関する基本要件

* CUSTOMER は他ユーザーの予約を操作できないこと。
* CUSTOMER は宿泊施設の登録権限を持たないこと。
* HOST は宿泊施設を登録・管理できること。
* HOST は予約確認などの管理操作を無条件に実行できないこと。
* OWNER は所属するTenant内の管理業務を実施できること。
* ADMIN はシステム管理業務を実施できること。
* SUPER_ADMIN はシステム全体を管理できること。
* 利用者は、自身に許可されていない業務を実行できないこと。

※ 本項では「誰が何をできるか」のみを定義し、具体的な認可方式は基本設計で定義する。

# 12. セキュリティ要件

## 12.1 認証

認証されていないユーザーは、認証を必要とする機能を利用できないこと。

## 12.2 認可

ユーザーは、自身に許可されていない操作を実行できないこと。

## 12.3 データ保護

ユーザー情報、予約情報その他の業務データについて、権限のない利用者からアクセスされないこと。

## 12.4 所有権保護

利用者は、許可されていない他ユーザーの所有リソースを変更・削除できないこと。

## 12.5 操作履歴

重要な管理操作について、操作履歴を追跡できること。

# 14. 移行要件

現行システムまたは既存データが存在する場合、必要なユーザー、宿泊施設、予約等の業務データを本システムへ移行できること。

移行対象データ、移行方法、移行手順および移行スケジュールについては、実際の移行対象が確定した段階で別途定義する。

# 15. 対象外・制約事項

現時点では以下を本要件の対象外とする。

* 完全自動の予約判断
* 完全自動の管理者判断
* AIによる最終的な業務判断
* 人間の承認を必要とする業務の完全自動化
* 要件として明示されていない外部システムとの連携

また、具体的なシステム構成、データベース構造、API構造、認可アーキテクチャおよびプログラム構造については、本要件定義書では規定せず、基本設計・詳細設計にて定義する。

---

# 16. 要件定義まとめ

本システムは、

> **「宿泊施設を管理し、宿泊者の予約を受け付け、運営主体ごとに適切な業務管理を行うためのシステム」**

とする。

また、権限については、

> **「利用者が誰であるか」だけでなく、所属する組織および担当する業務範囲に応じて、利用可能な業務を制御する。**

ことを基本要件とする。

本要件定義では、システムが実現すべき業務・機能・品質・権限・運用範囲を定義し、具体的な実現方式については基本設計以降で定義する。
